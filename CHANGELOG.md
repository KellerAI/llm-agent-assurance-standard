  - At a zero escape-rate tolerance (CT4 by default, `data.json:15`) the over-tolerance comparison is skipped for a Bucket-A or human-gated action (`laas.rego:318-356`; comparison `laas.rego:343-346`). A non-blocked, non-Bucket-A action that records `residual_error_bound` exactly `0` now fires `LAAS-OBL-RES-001` (`laas.rego:348-356`). The rule keys on a zero tolerance, not on CT4 as such.

  - Migration: a CT4 Bucket-A or human-gated record with a bound > 0 that previously failed `LAAS-OBL-RES-001` now conforms; a non-blocked, non-Bucket-A record carrying bound `0` at CT4 now fails.

In all nine industry profiles the §4.3 residual-risk template carries the exact-verified and open-world claim classes, escapes and samples, bound with confidence and method, tolerance, and verdict with evidence ID, and the §4.4 verifier template restricts `abstain` to model and human verifiers.   - SD-1: an undetermined tier fails closed to CT4. `expected_ct` is 0 only when `action.effect_surface.external_effect` is boolean `false` (`laas.rego:34`). Absent, null, or non-boolean values yield CT4 (`laas.rego:30`), and the lattice branch requires `true` (`laas.rego:39`). Per `standard/LAAS.md:43-44`. Records that omitted `effect_surface` previously evaluated as CT0.
  - SD-2: at CT4 (`human_approval_floor_ct`) a model-lineage verifier no longer satisfies independence. `LAAS-OBL-IND-001` fires for a passed `verifier.type == "model"` on a non-blocked action (`laas.rego:226`).   - SD-3: `LAAS-OBL-RES-001` also requires evidence referenced in the trace where a residual tolerance applies (CT2 and above) on non-blocked actions. Per `standard/LAAS.md:105-106`. New top-level input field: `evidence_refs`.

- **Breaking (major, per `CONTRIBUTING.md:56`; release number chosen at release time).** The LAAS policy fails closed on invalid gate and residual inputs (maintainer rulings R1 to R4, bead laas-szm); bundle `laas-fin-1.1.1` becomes `laas-fin-1.1.2` (`conformance/laas/data.json:3-4`):
  - R1/R2: a `gate.assigned_ct` that is absent or not an integer in 0..4 fires `LAAS-OBL-TIER-001` ("gate did not record an integer assigned_ct in 0..4; enforcing lattice ct N") on any record, blocked or not, and the gate tier falls back to the lattice `expected_ct` (`laas.rego:263-284`). `effective_ct` is the max of that gate tier and the window tier (`laas.rego:48`). The below-lattice TIER-001 and AGG-001 checks apply only to a valid `assigned_ct` (`laas.rego:103`, `laas.rego:135`), and SELF-001 compares against the gate tier (`laas.rego:109-111`). Records with no `gate.assigned_ct` previously skipped every tier-gated rule and reported compliant.
    - R2a: an integral-float `gate.assigned_ct` in 0..4 (for example `2.0`) is valid and is normalized to an integer before `effective_ct`, the residual-tolerance lookup, and every message (`laas.rego:306`). Such a float previously silenced `LAAS-OBL-RES-001` (fail-open) and rendered messages as `%!d(float64=N)`.
    - R2b: an integral-float `aggregate.window_effect_ct` (for example `4.0`) is normalized the same way (`laas.rego:50`, `laas.rego:311-316`). Non-integral values (for example `2.5`) keep the current behaviour.
  - R3/R3a/R3b: a `residual_error_bound` that is present, not `null`, and not a number >= 0 fires `LAAS-OBL-RES-001` ("residual_error_bound must be a number >= 0") at any CT, blocked or not (`laas.rego:286-301`). `null` is treated as absent. Only a valid bound is compared to the tolerance (`laas.rego:345`). A negative or non-numeric bound was previously compared cross-type or passed silently.
  - R4/R4a: bundle id `laas-fin-1.1.2` and `data.json` version `1.1.2`.
  - Migration: emitters must record an integer `gate.assigned_ct` in 0..4 and a `residual_error_bound` that is a number >= 0 or `null`.
